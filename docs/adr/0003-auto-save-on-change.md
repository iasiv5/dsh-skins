# 修改即自动保存，取代显式保存模型

---
status: accepted
date: 2026-08-31
supersedes: 0001-explicit-save-model.md
---

ADR-0001 在发布前把 v2.3 的"预览 + 400ms 防抖自动落库"改判为显式保存（点「保存」才写入，离开弹层确认放弃），本ADR记录 1.0.0 发布前实测后的再逆转：产品主人实测一周后裁决——保存仪式（每次编辑后找保存按钮、关闭时的"放弃未保存修改"弹窗、脏状态心智）对单人个性化场景是纯摩擦，真实收益（防误触、批量确认）未兑现；反而催生了"保存静默失败"这类只有显式模型才需要的错误处理盲区（实测问题 #7）。裁决：**修改即生效并自动保存**，删除手动保存与全部脏态确认。

## Decision

- **写穿（write-through）**：面板内任何字段变更（壁纸、中英标语、面板通透度；v2.5 裁决 #14 起原「面板不透明度、背景模糊、遮罩强度」三字段合并为一）经 400ms 防抖合并为一个 PATCH 自动落库；防抖窗口内的连续拖动只发一次请求。
- **「保存」「还原」按钮删除**：无独立预览层概念即无还原；预览机制仅作为内部投影管线保留，不再暴露为用户状态。
- **「恢复默认」保留**：语义为"全部字段立即重置为出厂默认并自动保存"（删除操作即时落库）。
- **脏态确认全部移除**：无脏状态即无"放弃未保存"问题——点空白、换肤按钮、Esc、齿轮收面板、卡片/齿轮切换面板目标，全部直接执行，不再确认（v2.4.1 #1 的"面板目标 ≡ 当前皮肤"不变式保留，仅去掉守卫）。
- **409 冲突自动化解**：自动拉取新快照并以新 baseRevision 自动重试一次；仍失败才上浮警示条。
- **非 409 失败警示**：沿用实测问题 #7 的机制——警示条携带服务器原因，下次编辑自动清除。

## Consequences

- 请求量回升（防抖后每编辑回合约一个 PATCH）；离线/只读时控件仍禁用，不产生积压队列。
- 弹层关闭时若有在途防抖，自动保存由会话级全局客户端完成，与弹层生死无关——v2.3"关弹层即冲刷"的时序隐患不复存在。
- "编辑后反悔"只能再次编辑（恢复默认可整体回厂）；这是即时生效模型的固有代价，产品主人接受。
- Y6 语义二次翻转（v2.3 自动 → v2.4 显式 → v2.5 自动）：两次转向的真实依据都是当期实测，本ADR如实记录振荡，1.x 若再翻转须有新实测依据。
- 取舍记录：ADR-0001 的"显式提交对话框心智"让位于"所见即所得"心智。

## Amendments

- **2026-09-01（v2.5 用户裁决 #14）**：tgcf 个性化字段由五个合并为三个——「面板不透明度/背景模糊/遮罩强度」合并为单一「面板通透度」（曲线联动派生三层视觉）。本ADR的自动保存语义不变，仅字段枚举随字段现实更新；合并决策的完整记录见设计文档 §7.2 裁决 #14。未新立 ADR：1.0.0 未发布，无外部存量数据，无可逆性损失。
