# 文字纱与文字地板：壁纸暴露区的常驻文字对比度保证

---
status: accepted
date: 2026-11-14
---

## 背景

2026-11-14 对比度基线（`01_docs/dsh-skins-audit/contrast-baseline-2026-11-14.md`，仓内 11 张出厂实拍 × Otsu 双聚类 × WCAG 相对亮度）证实：

1. **失败面 = 壁纸暴露面，不随皮肤身份**。meirenzhi 亮色 Web 出厂 35% 下 27 个有效测量行 20 行失败（74%）：侧栏 1.54–2.73x、品牌字标 1.29–1.96x、输入框占位 1.43–3.08x、底栏 1.52–2.73x，全部低于 4.5:1；新会话输入框容器边缘 1.00x（物理不可见）。
2. **纱厚处全部通过**：同一皮肤，深色纱厚侧栏 8.15–11.6x、Desktop 实体外壳 11.5x 达标；Desktop 会话区（壁纸区）占位 1.95x 失败——规律同构。
3. **双侧推导证伪单侧修复**：纯中性纱达标需 α>0.6（多数行），纯文字侧需亮色文字暗到 L≈0.003–0.07——都不可接受；两侧分摊（纱 +25 α 点 + 文字暗化到 L≈0.06）联合可达标。hero 标语文字侧 ΔL 很小（0.223→0.184）完全可行。
4. **结构缺口**：ADR-0010 的出厂语义变量只有纱 α、blurPx、玻璃三项，被否方案①脚注写着「文字刺眼」但文字对比度从未成为机制变量；openbmc/uefi 的**用户上传壁纸不上任何纱**（baked scrim 只烤内置图串，ADR-0004:17 遗留），上传壁纸下对比度比出厂更糟。
5. ADR-0004 字节等价不变式已随 ADR-0017 收档退役，存活的是手抄金值断言（值级）——统一机制改动 openbmc/uefi 只需按 ADR-0010 先例更新 GOLD 表，无不变式阻挡。

仓库既有「文字保护」词族（霜面底 ADR-0020、阅读底 ADR-0022）全部裁定**实底**直盖，管的是插件页/全屏面板；壁纸透出的宿主内容区是新的表面类——壁纸透出本身是产品价值，实底方案不适用，需要半透明但有上限的新成员。

## Decision

**机制（文字地板 = 保证属性，由两层联合达成）**：

1. **文字纱（背景侧）＝随动 token 的地板钳制**。投影核 `alpha` 派生规则扩展：riding 条目值形状从 `[rgb, baked]` 扩为 `[rgb, baked, floor?]`，派生 alpha = `max(pt(baked), floor)`（两位小数格式规则不变，ADR-0004:16 沿用）。被钳 token：`--dsw-specific-sidebar-fill`（侧栏列）与 `--dsw-specific-input-major`（输入框面）。**地板增量上限 +25 α 点**（相对各皮 baked 值），地板随构造在低 P 生效——0% 语义随之修订（见下）。`--dsw-specific-input-major` 因「输入框实体面」裁定（本表第 3 条）不受 +25 上限约束，其地板值由边界目标反推。
2. **文字色地板（前景侧）**。壁纸暴露区文字色须与保守背景估计（内置壁纸分区亮度 p95）保持极性感知最低对比度；通道按取证裁决——宿主存在可骑的文字色 token 则走 constantTokens，否则走 staticCss 结构局部名规则并进 verify-upstream-hooks 守卫清单。official 态由构造豁免（无声明表即无地板）。
3. **输入框实体面 + 边界**。composer 容器按 WCAG 1.4.11 直接做到组件边界 3:1：面 alpha 地板抬至近实色（值由门禁反推），边界以 staticCss 常量边框达成（结构局部名经活体取证钉住）。
4. **hero 标语与品牌位走文字侧**。hero 经宿主 DOM 钩子（活体取证发现类名/ token，守卫钉住）做文字色/影修法；品牌位是插件自有组件（MeiRenZhiName 渐变等），直接改组件 CSS。不给 hero 加衬底带——保住 ADR-0010「会话区壁纸原生锐度」卖点。
5. **阈值口径**：正文 4.5:1、大字（hero 标语）3.0:1、组件边界（1.4.11）3:1；hero 走大字线。
6. **出厂值不动**：35/55/66 保持（ADR-0010 铰链原点不动）；推导已证调参不能单独达标，地板是正解。
7. **硬门禁**：`scripts/verify-contrast.mjs` 进 `pnpm run check`——预计算内置壁纸分区亮度统计 fixture（含壁纸 sha256 防陈旧）× 测试侧独立重实现的投影公式 × 手抄 TEXT_FLOOR 文字色金值表，逐壁纸 × 皮肤 × 明暗 × web/desktop 出厂断言；门禁红灯允许「显式设计复审」不允许静默放行。用户上传壁纸不在门禁覆盖内，由机制（钳制常在）兜底。
8. **0% 语义修订**：「0% 纯壁纸完全透出」修订为「0% = 除文字纱地板外全透」（GLOSSARY「通透度」词条同步）；地板无例外是地板的定义。
9. **统一施加**：三皮一致（含 openbmc/uefi——其出厂达标但低 P 与用户壁纸面同样暴露；其 GOLD 表按惯例同步）。

**范围**：本 ADR 只覆盖基线实测到的表面（侧栏列、composer、hero、品牌位、底栏〔随侧栏列一并被纱覆盖〕，Desktop 会话区同构适用）。会话区气泡/消息面未测，明确不在本轮——留待后续对比度审计二期。

## Consequences

- **金值大面积更新**（ADR-0010 先例流程）：`tests/translucency-contract.test.mjs` GOLD 表 riding 条目增加 floor 列；三皮 riding 值变动的派生串变化逐一手抄更新；`tests/meirenzhi-skin.test.mjs`、`tests/personalization-projector.test.mjs`、`smoke-test.cjs` 相应断言同步。
- **用户可见变化申报**：meirenzhi 亮色出厂侧栏变实一档（fill 0.40→地板值）、输入框面变实并出现可见边界、品牌字标/标语文字色加深；openbmc/uefi 出厂观感近零变化（已达标，地板只在其 baked 以下生效），低 P 与用户壁纸下变化显著（变好）。
- **riding 值形状扩展**是投影声明表内部的值域变化，ADR-0014 生产面七字段与声明表 12 字段集冻结不破。
- 门禁 fixture 的分区统计是参考视口（1912×948）下的 cover-fit 采样近似，p95 取向保守；美学终审仍以主人实机目检为准（ADR-0010 Q7 惯例），门禁只裁文字对比度地板。
- `screenshots.json` 为零消费者孤儿文件，本战役实施时顺势退役或由门禁收编（实施计划裁定）。
- 二期（会话区消息面）不在本 ADR 承诺内。

- **R2.5（4 条，双侧推导触发）**：文字色地板升格为一等组件（例外阀被推导数据开启）· composer 实体面+边框直接 3:1 · 亮度纠缠三行实施前全分辨率实机复核 · 三件套（ADR/GLOSSARY/计划）。
- **R3（5 条）**：落位走声明表→投影核（official 由构造豁免）· α 增量上限 0.25 · 出厂值 35/55/66 不动 · 门禁离线解析式零依赖 · 术语两词条定稿。
